## 本次修复与发布准备

- 阻止数据库会话摘要被直接当作 Bearer 登录；会话绑定原租户。
- 空安装管理员原子创建，不重置/提升既有账户；移除固定凭据迁移和自动管理员升级。
- 仅任务创建者可确认执行；积分扣款、重试、退款与执行者归属一致。
- 修复租约接管条件、失败持久化与补偿恢复；旧 worker 不得退款或覆盖新执行者。
- 禁止上游重定向转发凭据，隐藏供应商错误正文中的密钥；收紧图片下载地址边界。
- 前端工作台和简报均使用同源 API；移除旧运营域名回退和废弃登录耦合。
- 合成演示在后端、UI、模型、概念图和决策门禁中一致标记，不升级为真实证据。
- 移除原站秘密、私有资料和未确认再分发权利的视觉资产；使用原创合成 VOC 和 SVG。
- 补齐初始化、部署检查、独立本地冒烟、CI、许可、说明书和截图；清理前端死代码及 Hook 依赖。
- 修正 ZIP 无 Git 安装后的审计边界；部署者自己的资源 ID 作为复核项，公共发布 CI 仍严格禁止携带。
- 修正全新环境下的检查顺序：`audit:reports` 自动生成其所需前端依赖，不依赖本机既有构建产物。首次 Linux CI 的 479 项测试已通过，随后暴露此缺失前置步骤；v1.6.2 修复该问题。

## 结果如何理解

报告结构审计覆盖五份参考报告：旧式 fallback 为 0、无法解析的必需来源路径为 0、无法证明的渲染来源绑定为 0。仍有 760 个明确待补证据的契约块；这不是“已有充分真实数据”。审计中的 grounded 仅指渲染绑定到报告字段，不证明事实准确或样本有代表性。

负载基线只访问临时本地数据库和模拟环境，付费服务始终关闭；场景包括健康检查、静态资源、登录限流、报告读取/304、幂等创建、并发签核、大 JSON 导出及 Queue 完成。它没有测量生产 Cloudflare 网络、供应商额度或真实大规模租户负载。

ZIP 验证使用已有 pnpm 包缓存，495 个依赖包复用、0 下载。Windows 跨盘默认 store 不同，第一次离线安装因空缓存失败；指定已有 store 后成功。这是离线包缓存条件，不是源码依赖缺失。普通首次安装需要联网下载依赖；发行 ZIP 不附带 node_modules。

未执行真实云部署、真实供应商付费任务、真实支付或全浏览器视觉认证。外部集成、数据授权、目标环境容量与灾备仍需部署者验证，详见 LIMITATIONS.md。
